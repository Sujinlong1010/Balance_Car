# 平衡车遥控 · 安卓 App（uni-app + 经典蓝牙 SPP）

手机端上位机，替代电脑上的 `Tools/PID_Tuner/pid_tuner.py`。
**不用改固件**——发的还是同一套 ASCII 协议（`MOV` / `SET` / `BAL` / `CAL` / `BST`）。

功能：驾驶（双杆摇杆 + 限速）、三环 7 项增益调参、实时波形、参数存档、通信日志。

---

## 一、为什么用 Native.js 而不是 uni.bluetooth

uni-app / 5+ 的蓝牙 API **只实现 BLE（GATT）**，官方文档写明"仅支持低功耗蓝牙 ble
传输协议，不支持蓝牙设备的配对连接传输大量数据"。你的 **HC-05 是经典蓝牙 SPP
（RFCOMM 串口透传）**，用 `uni.openBluetoothAdapter` 永远搜不到它。

所以这里用 `plus.android`（Native.js）直接调安卓原生 `BluetoothSocket`：

| 环节 | 做法 | 为什么 |
| --- | --- | --- |
| 发送 | `DataOutputStream.writeBytes(String)` | 避免在 JS 里手工构造 `byte[]`（Native.js 的老坑） |
| 接收 | `BufferedReader.ready()` 判断后再 `readLine()` | `readLine()` 单独用会阻塞 WebView 主线程卡死界面 |
| 协议 | LF 分隔的 ASCII 行 | 正好和 `readLine()` 一位对一位，天然分帧 |
| 连接 | 标准 SPP UUID `00001101-0000-1000-8000-00805F9B34FB` | HC-05 出厂就是这个服务 |

代码在 `common/spp.js`（蓝牙）和 `common/protocol.js`（协议，纯函数可单测）。

## 三、从零到装上手机（约 15 分钟）

### 1. 装 HBuilderX

<https://www.dcloud.io/hbuilderx.html> → 下载「标准版」→ 解压即用（免安装）。
启动后若提示「安装 App 开发插件」，点确定装上（云打包必需）。

### 2. 打开本工程

HBuilderX 菜单 **文件 → 打开目录** → 选 `Tools/Mobile_App`。
左侧出现 `pages / common / manifest.json / pages.json` 就是识别成 uni-app 项目了。

工程用的是 **Vue 2**（`manifest.json` 里 `"vueVersion": "2"`），HBuilderX 4.x 直接支持，
不用改。

### 3. 补一个 AppID（唯一必做的手动步骤）

双击 `manifest.json` → 底部「基础配置」→ 点 **「重新获取」/「获取 AppID」** →
登录 DCloud 账号（免费注册）→ 自动填进去。

> 没有 AppID 云端打包会直接报错。这一步只做一次。

`manifest.json` 里已经预置了蓝牙权限（含 Android 12+ 的
`BLUETOOTH_CONNECT` / `BLUETOOTH_SCAN`），不用再手动加。

### 4. 手机先配对 HC-05

**系统设置 → 蓝牙** → 打开 → 搜索 `HC-05` → 配对，PIN 输入 **`1234`**（有些模块是 `0000`）。

App 只列「已配对」设备，因为 SPP 不能靠扫描发现，必须先配对再连接。

### 5. 真机运行（推荐先这样试通再打包）

手机打开 **开发者选项 → USB 调试**，USB 连电脑。
HBuilderX 菜单 **运行 → 运行到手机或模拟器 → 运行到 Android App 基座**。

首次会往手机装一个「HBuilder 基座」，之后改代码点刷新就生效，**不消耗打包次数**。
调试阶段全程用基座，别反复云打包。

### 6. 云打包出 APK

**发行 → 原生 App-云打包**：

- 勾选 **Android（apk 包）**
- 证书选 **「使用云端证书」**（不要再选公共测试证书，已停用）
- 打包方式选 **「安心打包」**（不上传代码，更快）
- 取消勾选 iOS

点「打包」，等 1–3 分钟，完成后会给出 APK 下载地址（也在
<https://dev.dcloud.net.cn> 的「打包记录」里）。

### 7. 装到手机

USB 拷过去 / 微信传到「文件传输助手」/ QQ 传，点开安装。
会提示「未知来源」「应用未备案」——选继续安装，自用没问题。

## 四、怎么用

1. 小车先架空（轮子悬空），手机连 App → 点右上「连接」→ 选 HC-05。
2. 连上会自动读回三组增益，确认手机上显示的和车上一致。
3. 点「扶正标定」→ 车扶正静止 1 秒。
4. 点「开始平衡」→ 轮子开始转，架空状态下推左杆前后、推右杆左右，确认**转向和前后都正确**。
5. 放地上，手虚扶着，左杆轻轻往前推一点。反了就先急停，改固件
   `app_balance.h` 的 `APP_BAL_MOVE_FWD_SIGN` / `APP_BAL_MOVE_TURN_SIGN`。

**双杆怎么用**：

左边一根杆管**前后**（往上推 = 前进），右边一根杆管**左右**（往右推 = 右转）。
两轴完全独立，所以能一边前进一边转弯。

- 杆是**比例**的：推一半就是一半速度，不是"一按就满"。
- **不推 = 杆在中间 = 原地停住**，不需要专门点刹车。
- 松手（`touchend`）立刻归零并发 `MOV,0,0`，手柄有弹回动画。
- 中位有 6% 死区，手指没真动时不会让车蠕动。
- 拖动时 60 ms 节流直发，手感跟手；100 ms 心跳兜底。
- **两根杆可以同时推**（各用一根手指），边前进边转弯。推的时候下方会显示
  「触点 2」——看到这个数字是 2 就说明手机确实在报两个触点。
- 「回中」按钮 = 两根杆一起归零，慌的时候按这个。

**为什么手势挂在外层容器上**：安卓 WebView 只把触摸流派给「手指按下时所在的那个
元素」。如果把 `touchstart` 分别挂在两根杆上，第二根手指落下后，第一根手指的
`touchmove` 就收不到了，表现正好是「不能同时推」。所以现在整个 `.sticks` 容器
统一收事件，再用 `touch.identifier` 判断每根手指管哪根杆——这也顺带解决了
「手指从杆上滑出去就断」的问题。

**安全机制（已经做进固件和 App 里）**：

- 摇杆**推着才走，松手立刻停**（`touchend` 就发 `MOV,0,0`）。
- App 每 100 ms 发一次心跳，固件 600 ms 收不到就自己斜坡停车。
  所以**手机切后台、锁屏、蓝牙掉线、App 崩了，车都会自己停**。
- 点「急停」= 先发 `MOV,0,0` 再发 `BAL,0`，两步都做。
- 「开始平衡」会先把两根杆清零，必须重新推才动，防止一点使能就冲出去。

## 五、常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| 点「开始平衡」→ `BAL,1 rejected - CAL still at 40%` | 标定还没结束。CAL 要**连续静止 1 秒**（100 个样本），中间一抖就清零重来。扶着别动，等状态徽标从 `CAL` 变回 `IDLE`（进度 100%） |
| 点「开始平衡」→ `BAL,1 rejected - tilt +19.3 deg (limit 12)` | 车身倾角超过 12°，扶到竖直再点。如果扶正了角度还是很大，说明标定值不对（标定时车不是竖直的），重做一次 CAL |
| 点「开始平衡」→ `BAL,1 rejected - IMU not responding` | MPU6050 读不到数据，查 I2C 接线/供电，看是否有 `LOG,MPU6050 init failed` |
| 点连接提示"没有可用设备" | 没配对。先去系统设置蓝牙里配对 HC-05（PIN 1234） |
| 提示"蓝牙未开启" | 系统蓝牙开关没开；或 App 没有蓝牙权限（设置 → 应用 → 权限 → 附近设备） |
| `Service discovery failed` / connect 失败 | HC-05 已被电脑或其他手机连着（SPP 同时只能一个连接）。断开电脑端再试；或模块没上电 |
| 连上后没数据 | 波特率不用管（SPP 透传），但固件那边要是最新的 hex；看「存档/日志」页有没有 `LOG,PID tuner ready` |
| 摇杆推了车不动 | 没点「开始平衡」（状态不是 RUN），日志里会有"小车未使能"提示 |
| 两根杆不能同时推 | 先看下方有没有「触点 2」。有 2 说明手机没问题，是事件挂错了地方（要挂在容器上）；连「触点 2」都不出现，才是屏幕只支持单点——那种屏只能一次推一根杆 |
| 波形是一条直线 | 纵轴现在自动量程了，静止时确实就是一条直线。想确认在不在动，看左上角的 `±N°`，它会跟着峰值变 |
| 波形一冲一出框 | 量程只在峰值顶出去时放大，放大那一帧可能短暂削顶，下一秒就正常 |
| 摇杆一松就停 / 推到底也不快 | 正常。杆是比例的，推一半只有一半速度；想要更快就把「限速」滑到 100% |
| 杆推着推着跑偏 | 中位死区只有 6%，手指出汗容易飘。松手让它归零再推 |
| 按住走一下就停 | 心跳被系统掐了（省电策略）。把 App 加进电池优化白名单 |
| 打包报"公共测试证书不再支持" | 证书改选「使用云端证书」 |
| 打包报 appid 为空 | 按上面第 3 步补 AppID |

## 六、代码结构

```
Mobile_App/
├── manifest.json          App 配置（appid、蓝牙权限、打包参数）
├── pages.json             页面路由
├── main.js                Vue 2 入口
├── App.vue                启动时申请蓝牙运行时权限
├── common/
│   ├── protocol.js        协议：组帧 + 解析（纯函数，可用 node 直接测）
│   ├── chart.js           波形纵轴量程计算（纯函数，可用 node 直接测）
│   └── spp.js             经典蓝牙 SPP 封装（Native.js）
└── pages/index/index.vue  界面：驾驶 / 调参 / 存档三个页签
```

想改 UI 的配色，集中在 `index.vue` 底部 `<style>` 里；
想改限速/步进范围，改 `data()` 里的 `specs` 和 `pct`。

**单测**（不需要手机、不需要 HBuilderX，只要有 Node）：

```bash
node Tools/Mobile_App/test/protocol.test.mjs
# -> PROTOCOL_OK  55 checks, 0 failure

node Tools/Mobile_App/test/chart.test.mjs
# -> CHART_OK  22 checks, 0 failure
```

协议覆盖：组帧与夹紧、T/BST/ACK/ACKV/ACKT/ACKM/LOG 解析、旧固件 9/11 段 BST 兼容、
12 条畸形输入不崩。量程覆盖：档位选择、迟滞（峰值小幅波动时量程不许动）、
掉零后重新倾斜。改完对应文件跑一遍就知道有没有弄坏。
